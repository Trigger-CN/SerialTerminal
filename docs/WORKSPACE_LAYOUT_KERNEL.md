# 统一布局内核重构契约

> 状态：统一 Split/Stack 内核已接入生产代码；模型/VM/fake-DOM 自动化见 §8。原生交互、实际重启与硬件验收仍待用户执行，不视为整体验收完成。
> 取代现有外层扁平列、Shell 独立列特例及区域投影的运行态设计。串口业务隔离、统一事务和终端资源实例保留。
> 手动验收由用户执行；代理不截图、不启动或操作用户正在测试的应用。

## 1. 已确认的问题及重构边界

基线 `c910694`。真实 renderer 菜单处理函数与 tab-model 联合探针确认：

- 两组分屏后分离 Shell 共三列，取消第二组分屏会先把全部 ownColumn Shell 改回 row，再派发不带局部目标的 column-split:false，三列变一列。
- 多组 Shell 的普通 split-tab 被拒；第二个 Shell 再执行独立成列仍加入同一个 __shell__ 区域。
- 对单个已分离串口组请求改变排列轴向，会改变全局外层方向。
- 旧回归曾断言关闭组分屏后只剩一列；本轮必须依据产品行为修正期望，不能继续将旧实现当作规范。

这些探针没有运行原生菜单、真实拖拽或物理串口。历史全量通过不构成本轮完成证据。

保留：串口连接/日志/发送隔离、业务 stores、唯一 workspaceModel、克隆后原子发布的动作入口、按钮/面板/xterm/parser/PTY 身份。
替换：几何表达、位置查询、局部合并、四方向分屏、分隔条定位、布局快照及相应菜单/拖拽适配。禁止无关发布、线程和依赖变更。

## 2. 身份、归属与几何分离

- tabId 是业务标签身份；ownerGroupId 是串口业务归属；布局移动不改变 owner。
- layoutNodeId 是独立且稳定的几何身份，不能使用 groupId、tabId 或 __shell__ 充当通用区域身份。
- 几何仅使用两种节点：Split（方向、子节点、比例）和 Stack（成员有序列表、局部 active）。外层和组内使用同一种节点算法，不各自实现拆分、收敛和 resize。
- 串口组是业务容器及多组放置边界，不是全局分屏开关。Shell 是普通叶标签，不是伪串口组。
- 几何存储只持有身份引用；TabRow/subRow 的显示角色由业务模式和所在层级派生，不是额外可写成员表。
- 每个叶标签只有一个实际挂载位置；每格独立 active，输入焦点 focusedTabId 与侧栏控制组 activeGroupId 分开。

### 2.1 唯一树的具体表达

`workspaceModel` 只保存 `tabs` 业务身份清单、`focusedTabId` 与 `layout`；`layout.root` 是唯一几何树。节点使用独立 ID：

```text
Split { id, type: split, orientation, children[], weights[] }
Stack { id, type: stack, items[], activeItemId }
成员 { id, tabId, content? }
```

- 叶成员直接引用业务 tabId；组成员引用业务 groupId，并以 content **实际拥有**一棵同构 Split/Stack 子树。content 不是另一份成员表或 pane 投影。
- 单组时树直接放置所有叶，组边界仅在查询中由 owner 派生；多组时根级 Stack 只接受组成员及 Shell，组 content 只接受其 owner 的串口叶。
- 单→多逐个现存 Stack 包装串口成员，Shell 留在原节点；同一组必要时可以有多个布局锚点，各自实际拥有不同叶子，不重复挂载。同一业务组的多个锚点不创建多份串口业务实例，按钮以成员 ID 区别几何锚点。
- 多→单解包组成员的 content；保留 Split 的相对方向、局部比例与现存 Shell 节点。混合根格将 Shell 按原先前后关系并入选中 content 的局部 Stack。同格若有多个同 owner 锚点，完整 content 子树按原锚点顺序组成新的横向等比例外层，保留各子树内部轴向、比例、节点与选择；不承诺原先隐藏的多个内容都保持原绝对矩形。
- 创建组不自动拆根树；新组加入当前合法根格（焦点在 Shell-only 区时，选择布局顺序中首个有串口组的根格）。
- 分组菜单对被点击的布局锚点操作；没有传锚点时优先焦点所在锚点，再取该组首个锚点。组关闭仍关闭整个业务组及其全部串口叶；局部合并只搬对应锚点。
- `mergeOrigins` 只记录成员分离前的 Stack ID，供默认局部合并目标选择；它不是位置真源。节点清理不会用这份提示重造区域。
- 兼容 pane/column 查询可以返回一次性只读派生结果，但运行态不得保存或反向导入这些结果；所有写入必须操作同一棵树。

## 3. 动作契约

所有入口通过同一事务，菜单能力查询与执行共享准入规则。

| 动作 | 必须携带 | 语义 |
| --- | --- | --- |
| activate | tabId、实际区域身份 | 只改变所在格 active；按业务 owner 同步控制目标 |
| move | source、target Stack、插入位置 | 搬已有成员，不隐式建立分屏 |
| split | source、target 区域、left/right/top/bottom | 仅拆目标局部区域；不同分支方向互不影响 |
| merge | source、target Stack | 只撤销指定标签/组的布局分离，保留无关区域 |
| collapse-all | 明确作用域 | 显式收起该作用域全部分屏，不复用局部关闭入口 |
| resize | splitNodeId、相邻子节点、比例 | 只改对应 Split 的相邻分配，不重置第三格 |
| close | tabId 或 groupId | 业务关闭，不等同于取消布局分离 |
| restore | 版本化布局快照、合法业务身份清单 | 在恢复边界一次发布，不逐格保存半成品 |

分屏方向不是 horizontal/vertical 布尔轴向的别名：left 与 right 必须产生相反且可预测的相对位置。内部可将四方向转换成轴向及子节点顺序。

### 3.1 默认目标选择

- 菜单作用于被右键的标签/组所在区域，不读取旁边的当前控制组代替目标。
- 同一 Stack 有其他成员时，从该 Stack 拆出被操作成员，插在剩余内容的指定侧。
- 来源已独占一个区域时，不生成空区域；可相对同作用域的有效相邻区域重排。没有合法目标则禁用并给出原因。
- “取消此组分屏”优先合入其分离前的有效来源；来源已失效则选择同作用域最近的合法串口区域，先前后后。不得选择无关 Shell-only 区域作为默认回收站。
- 如无合法合并目标则禁用。不能退化为全局折叠或关闭业务组。
- “合并到另一分屏”的目标必须是现存 Stack，绝不借用新建分屏动作。
- 操作时目标失效必须原子拒绝并提示，不发布部分 Shell 位置修改。

### 3.2 局部性要求

只改变来源、目标及其必要祖先路径；无关分支的成员、顺序、active、方向和内部比例保持不变。空来源与实际目标在同作用域的兼容同轴路径时，将释放份额交给目标；否则按局部兄弟收敛，不全局均分尺寸。非相邻/混合轴合并受几何约束，不承诺所有区域的绝对像素位置永不变化。

## 4. 单多组模式

- 单组默认扁平，无 subRow；main/filter/chart/Shell 可自由跨格移动，owner 不变。
- 用户显式开启组内分屏按既有方案 A 显示各格 subRow；关闭后恢复扁平。
- 多组时串口叶不得脱离所属组，Shell 位于根级；根 Shell 与组标签共享外层 Stack 放置与分屏机制。
- 单多切换必须是同一次原子结构转换：先计算合法目标，再移动身份引用，再清空节点并发布。不得通过重建终端完成转换。
- 已有 Shell-only 区域保持独立与相对次序，不因添加组自动合并；串口叶按 owner 保持业务边界，新组加入合法串口区域并保持 disconnected。
- 混合格及同组串口多格转换必须有明确的迁移测试；如果层级边界必须调整，需保留可保留的区域、顺序、局部选择和比例，不静默全局折叠。
- 回单组恢复统一放置准入，既有 Shell 分支仍存在；不把多组禁入规则永久残留在菜单或拖拽入口。
- 收起标签栏与合并几何是两个动作。至少两个真实 Stack 才可收起；首个可见标签栏保留展开控件（锚点切换后重新派生），其余 header 隐藏但已选面板继续显示，合并不足两格自动展开。显式 `collapse-all(scopeGroupId)` 汇聚该 owner 的全部锚点，不收集 Shell 或其他组。

## 5. 生产接管与旧态删除

1. 先用本轮组合和不变量建立失败回归，再实现纯几何原语与事务。
2. 在现有 workspaceModel 中替换几何内核；模块拆分可复用纯函数，但不能建立独立的第二个可写 Workspace。
3. 同步接管模型查询/能力、manager 适配、原生菜单 IPC、标签栏/内容区菜单、拖拽目标、激活、关闭、组增删、分隔条及 fit。
4. render plan 表达真实嵌套几何，协调器按稳定节点身份复用 DOM。不能将新树重新压回单一全局方向的扁平列再渲染。
5. 新运行态不再写 columnMode、隐式 Shell 列或 paneIds 投影；过渡兼容数据仅为只读派生，不能反向重建运行态。
6. 迁移接通并验证后删除旧几何执行分支；不保留长期并行新旧布局策略或静默 fallback。

## 6. 保存与恢复

- 当前配置 schema 为 **17**，布局快照为 **2**。v1 列/pane/ownColumn 仅在单向迁移边界读取；v2 保存实际树及各组顺序、收起和最近焦点。
- 迁移输入为合法业务身份及旧 v1 布局；覆盖扁平、显式列、隐式 ownColumn、Shell-only 区域、pane 投影、顺序/active/比例及单多组状态。
- 迁移确定且幂等；过滤无效/重复位置，补回有业务实例但漏位置的叶，不合成终端或业务组。
- 新快照为几何唯一持久化来源，保存业务清单与布局仍使用既有完整快照合并保存边界。
- 未知版本不得破坏原始配置；异常迁移不能通过写入空白布局掩盖。
- 用户真实配置仅允许读取或复制到工作区隔离 profile，不允许代理改写。

## 7. 必须通过的验收

1. COM1/COM2/Shell 三个区域，取消 COM2 分屏后串口组同区，Shell 区域仍独立；业务组和 Shell 都不关闭。
2. Shell 向左和向右分屏有相反相对位置；两个 Shell 可分别占不同区域，不共享特殊列身份。
3. 一分支上下、另一分支左右；后续动作不改变无关分支的方向和内部比例。
4. 局部 merge、close、move、resize 保留其他格 active 和顺序；没有空幽灵区域或重复挂载。
5. 单组 main/filter/Shell 任意分屏拖动，新增第二组、关闭回单组、再次新增均保留合法布局与终端身份。
6. 菜单→IPC→handler→事务→render plan 与直接模型动作一致；标签栏与内容区能力一致。
7. 拖拽移动只到实际目标；相邻分隔条使用真实 splitNodeId，不依赖业务组 ID 猜测。
8. v1 迁移、新快照往返、坏引用去重、关闭后重新恢复保持顺序/active/方向/比例。
9. 操作序列覆盖先组后 Shell、先 Shell 后组、反复拆合和保存恢复；每步校验 owner 不变、唯一位置及原子失败。
10. 真实 xterm/PTY 生命周期不因布局变化重建，永久添加入口和统一二级行构造保持。

自动化需覆盖真实生产函数链，不只验证新模块自身。用户原生交互、实际重启及双端口/长时异常验收仍单独记录，不能被 VM/fake DOM 或历史 CDP 代替。

## 8. 实施记录

- 生产链路：`dispatchWorkspaceAction → applyWorkspaceAction → normalize/validate → buildRenderPlan → createLayoutRenderer`。根和组内复用 `layout-tree.js`，不再使用全局列方向、共享 `__shell__` 或 `paneIds` 投影执行布局。manager 仅返回派生副本、写统一动作。
- 四方向菜单覆盖组/普通标签/main/filter/chart/Shell，IPC 保留精确锚点；拖拽只移入可见的已有 Stack。创建入口永久共用，根级创建按点击区域寻找 owner；内容点击/focus 同步侧栏但不覆盖其他格 active。
- 递归协调器移动既有按钮/面板，保留终端资源引用；每个 Split 有 N−1 条 6px 分隔条，相邻 resize 按帧合并，释放后 flush 并执行最终 fit/PTY resize。只读诊断同样读取实际树和 Stack DOM。
- v1 导入及 v2 恢复对照真实业务清单过滤重复、未知和跨 owner 引用，补漏位置，不合成终端。分配器避开业务/节点/成员 ID；深损坏布局可回收至合法树。面板身份必须等于业务叶 ID。
- 主进程升级前备份旧 schema（例如 `config.v16.backup.json`，不覆盖既有备份）；读取/备份/不安全迁移失败进入本次运行写保护，普通保存和遥测保存均不改原文件，并在窗口加载后提示。未知布局版本不静默覆盖，未提供绕过保护的解锁。

### 8.1 用户手动验收清单

1. 单组 main/filter/chart/Shell 逐一左右上下拆分、拖入已有格，检查顺序和每格选择；唯一叶无合法邻居时禁用，不能出现空格。
2. Shell 已分屏调比例 → 添加第二组 → 关闭回单组 → 再添加：保留合法方向/比例/次序，新组 disconnected，Shell 不随组点击跳位。
3. 两个串口区域加最右 Shell 区域，取消一个串口组分屏：只合并该组，两个业务组不关闭/断开，独立 Shell 不被回收。
4. 左分支上下、右分支左右，拖每一条 gutter 并缩放窗口；检查所有终端跟随尺寸，松手后 Shell 光标/PTY 宽高正确。
5. 点击及键盘聚焦各组 main/filter/chart，侧栏跟随；点击 Shell 不改串口控制目标。检查两层相同永久添加入口和非控制组区域创建位置。
6. 正常关闭并重启，检查布局/顺序/局部选择；使用备份副本验证旧配置迁移。出现保护提示时本次不保存，先备份排查，不要依赖强制覆盖。
7. 可选真实双端口并发、日志目录/自动保存、发送/快捷触发隔离、长时最小化恢复和异常断开。以上原生/重启/硬件项均未由本轮自动化执行。
